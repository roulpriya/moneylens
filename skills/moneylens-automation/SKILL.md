# MoneyLens daily automation

Update the persistent spending ledger and the **same HTML report**. The user has authorized automatic saving of validated transactions during setup. Hold uncertain items for review. The UI is a Bun-built, committed single HTML asset at `assets/report-template.html`; normal runs change only the report's bounded JSON data block. Do not redesign the UI, edit the template/helpers/skills, modify Git, or generate a replacement layout.

For a personal note or categorization correction, use [personal context](references/personal-context.md) and refresh the report. A mailbox scan is unnecessary for a correction to already saved data.

## Preconditions

- Run `scripts/runtime_state.py status` for the configured data directory. Setup must be ready and have a confirmed account inventory. All runtime state defaults to `~/Documents/MoneyLens`; if the status command reports legacy storage, route to setup for migration rather than starting an empty ledger. If not, route to `$moneylens-setup`; do not start onboarding or create a schedule inside this skill.
- Verify the connected Gmail profile matches the configured mailbox on each run. Use connected Gmail tools, not the Electron adapter or scraped credentials. If unavailable/mismatched, preserve existing data/report and report the failure.
- Run `runtime_state.py begin-run` for the scan window, retry queue, configuration, and exclusive run ID. If another run holds the lease, stop without duplicating work. The initial window covers the previous calendar month and the current month; later windows overlap the last successful scan by three days to catch delayed emails. Revisit queued failures even if older than this window.

## Sync

1. **Fetch all sources.** Search for statement PDFs, successful card alerts, and UPI bank-account debits and credits, consume all pages, and deduplicate source IDs. Read real content to exclude promotions, payment reminders, OTPs, declined/reversed attempts, balance-only notices, and pending authorization holds. Alerts should describe a successful movement; do not infer transactions from available limits or account balances. Keep receipt-date scanning separate from transaction-date reporting. Read [Gmail and extraction](references/gmail-and-extraction.md).
2. **Identify the account.** Match card-backed movements only to a confirmed setup card using issuer and masked card evidence. Use its stored account key and Keychain scope; do not recompute identity from a different spelling of the issuer. A new/ambiguous card is queued for setup confirmation, not silently added. For bank-account UPI, infer the user-owned bank account from authenticated bank notices and retain it in `upi_accounts`; keep bank accounts separate from cards even when their last digits coincide. Do not require a card PDF password for a bank alert. Continue processing other accounts.
3. **Unlock PDFs without interaction.** Run `<data-dir>/runtime/bin/python scripts/pdf_extract.py` with `--no-prompt` and the confirmed scope. Never open a password dialog or try unrelated saved passwords. Missing/changed passwords, inaccessible Keychain, scanned-only/unsupported PDFs, and connector download failures go in the retry queue with a nonsecret reason. Continue other documents. Temporary PDFs, extraction JSON, and payload files are removed in `finally`; retain only structured records and Gmail provenance.
4. **Save and reconcile.** Read [ledger contract](references/ledger-contract.md). Stage extracted statements with `ledger.py stage`; automatically `import` records whose validation issues are empty. Never clear issues to force import. Missing independent totals are disclosed, not represented as passed. Ingest clear alert emails via `ledger.py alert` with one successful movement per payload; these are provisional until supported by a statement. Capture exact shared bank transaction references when present. The report reconciles shared references and unique one-to-one account/currency/amount/movement/normalized-merchant/date matches against saved statements. A missing opaque reference is not itself a warning. Repeated/conflicting candidates remain for review; use `reconcile` only with actual supporting evidence. Do not count an alert and its statement row twice. Preserve distinct identical purchases and corrections.
5. **Retry bookkeeping.** Use `runtime_state.py retry-add` for every failed/unresolved source not already represented by a staged issue; remove queue entries only after successful processing or a justified exclusion. A document failure does not make the whole mailbox scan incomplete if it is durably queued. A search/pagination/authentication failure does: keep the previous scan cursor.
For UPI use `channel: "upi"` and the correct `account_type`. A successful bank debit is `upi_debit`; a received amount is `upi_credit`, not automatically a refund or income. Explicit own-account transfers are `transfer_out`/`transfer_in` and excluded from spending. Card-bill payments remain repayments, not new expenses. Card-backed UPI stays on the confirmed card account and reconciles against its statement. The optional `gmail_transactions.py` helper covers observed HDFC/ICICI layouts; unfamiliar notices still require source-based interpretation, never silent omission.
6. **Update existing report data.** Run `ledger.py report --output <configured-report-path>`. Its default display range is the previous calendar month through today in the configured timezone; pass explicit dates only for a user-requested range. `begin-run` also returns these as `display_from` / `display_to`. Account discovery during setup has a separate 30-day window. This reads the committed template only when the report is first created; subsequent writes replace its JSON data block and preserve every byte outside it. Keep all ledger history. Do not delete/recreate an incompatible or damaged report; report the problem for setup repair. Use the same Documents report path every day, default `~/Documents/MoneyLens/report.html`, not a new dated report.
   Report generation automatically applies the user's private personal rules and transaction notes, including to newly ingested records. Preserve these during sync; do not replace rules with generic merchant guesses. Notes and rule-based assumptions are separate from bank evidence. For a user-requested category correction, personal note, or reusable rule, read [personal context](references/personal-context.md); save the change privately and refresh the same report. Do not put personal payee facts in this skill or Git.
7. **Complete the scan.** Call `runtime_state.py finish-run --run-id ID --search-complete` only after all search pages and source dispositions are durable and the report update succeeds. On a partial search or run error, finish with `--error` and no complete flag; never advance its cursor. Refresh report data after finishing to expose the latest sync/retry status. A run with zero new records still checks retries and updates its data status. Expired leases recover from crashes on later runs.

## Output

Stay quiet while the monitored state is unchanged or non-actionable. Notify on meaningful new data, completion of initial backfill, failure, a new card, changed password, or required review. Give a short delta and the **existing** report link. Keep non-actionable limitations and source diagnostics in collapsed report details. Show one grouped review summary for genuine unresolved items; do not dump one warning per email or treat expected alert reconciliation, unavailable optional checks, and UPI receipts as failures. Do not send email, change mailbox labels/read state, initiate payments, or schedule additional jobs.

Spending uses integer minor units, separate currencies, and transaction dates. Payments do not reduce spending; refunds do. Preserve category corrections. The ledger is local SQLite protected by file permissions, not application encryption. Full workflow/CLI details are in the linked references; PDF credentials never enter the database or report.
